# 模型发布研究框架

更新：2026-11-04。用于研究公开模型发布的产品信息、传播路径和用户需求，也可支持制定待验证的发布假设。

## 要回答的问题

1. 模型面向谁，解决什么任务？发布材料中的技术能力、演示和评测分别提供什么证据？
2. 发布时可以公开体验、受邀体验，还是只能观看演示？访问状态会改变内容、渠道与行动入口。
3. 哪些官方账号、研究者、开发者、媒体和社区参与传播？他们各自解释了什么？
4. 受众提出了哪些具体需求、疑问或替代方案？哪些反馈能回查原文？
5. 哪些动作适合借鉴，依赖什么资源、证据或时间窗口？

## 事件记录

| 字段 | 记录方式 |
|---|---|
| 发布事件 | 产品或模型名、版本、组织、官方公告与具体节点 |
| T0 | 发布时间，保留原始时区和 UTC；多阶段发布分开记录 |
| 开放状态 | 仅展示、受邀体验、公开服务或其他；附当时依据 |
| 目标受众和主张 | 官方的目标人群、应用场景、核心表达 |
| 证据和体验 | 技术报告、评测、真实演示、API、权重及使用入口的实际状态 |
| 传播 | 各平台的官方、员工、合作方和独立讨论；链接、作者与日期 |
| 承接 | 观看、候补、文档、试用或联系入口，以及各自限制 |
| 缺口 | 未采集、无法访问、未核实及可能影响 |

## 采集与比较

- 以具体事件为单位，优先考虑发布前 7 天、发布后 24 小时、7 天和 30 天；窗口以实际 T0 计算，未结束的窗口标记进行中。
- 按研究目的选择官网、博客、X、LinkedIn、YouTube、Reddit、Hacker News、GitHub、Hugging Face 及相关中文平台。记录实际查询范围、语言、分页、采集时间、失败和缺失。
- 官方内容、合作传播、独立反馈、产品使用、线索及收入分别记录。有限样本只报告已发现数量，不称全网声量；跨平台展示不能直接当作去重人数。
- 历史时间窗口的数据必须有对应时点快照；当前累计互动不能倒填成首日数据。网站流量估计与真实访问、注册或收入分别标注。
- 比较前核对账号基础、发布时开放程度、受众、资源和时间窗口；条件不同的事件作为参考，不直接排名。

## 阶段目标

先定义目标受众和可用的承接方式，再选择内容交付、讨论、访问、合格需求、体验和后续采用等指标。每个指标写明公式、来源、去重方式与时间窗；没有基线时保留假设，不把示意数字写成已验证目标。
